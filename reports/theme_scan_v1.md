# cc#1185 P1 — THEME SCAN v1

Read-only inventory of every visual primitive on the app surface. Generated by a declaration walk, not a grep: each rule is parsed, each property classified into the families the card names, and `var()` references separated from raw literals. CSS and HTML comments are MASKED before parsing — these sources are heavily commented and every hex code inside a comment would otherwise land in the inventory as a live primitive.

Every cell reads **total/raw** — declarations in that family, and how many of them carry a literal the token layer could have owned. A dash means the family is absent. `raw` is what P2 turns into the violations report and P4–P7 repoint; `total - raw` is already tokenised.

## 4. The token layer as it stands

| | count |
|---|---|
| custom properties DECLARED across the shared sheets | 128 |
| distinct tokens REFERENCED (`var(--x)`) anywhere | 88 |
| referenced but NEVER declared (resolve to their fallback, or to nothing) | 5 |
| declared but never referenced | 45 |

A token referenced but never declared is the quiet one. It does not error — it silently takes the inline fallback if the call site wrote one, and renders as *nothing* if it did not. Those are the keys P3's schema lock has to fill.

**Referenced but never declared (5):** `--mtable-bg`, `--rc`, `--t-sunk`, `--tkr-dur`, `--vc`

**Three of these are not schema keys and must not become any.** `--rc`, `--vc` and `--tkr-dur` are set INLINE, per element, from JavaScript — `style="--rc:${rc}"` on a rail card, `--vc` on a verdict row, `--tkr-dur` on the ticker to carry its scroll duration. They are runtime values, not theme values. A stylesheet scan cannot see a `style=` attribute, which is why they surface here; putting them in a theme set would be wrong, because a theme has no business deciding one card's rail colour. **P3 must skip these three.**

The other two are real gaps, and each is verified by a repo-wide search returning zero declarations:

- **`--t-sunk`** — referenced 3 times in `mobile/home.html` (`.nwtabs`, the sheet backdrop) and declared nowhere. It is the one missing member of an otherwise complete family, and that family is the finding below.
- **`--mtable-bg`** — referenced twice in `mobile.css` for the sticky table column and header, both with the fallback `#fff`. Nothing ever sets it, so the fallback is the value: **a white sticky header on a dark app**. That is a live defect, not just a missing key, and it is in the shell sheet so it reaches the web surface too. Naming it here rather than fixing it — P7 owns the repoint and this sprint may not change appearance.

### 4a. The `--t-*` family is declared FIVE TIMES, not once

The eleven `--t-*` keys (`--t-brand`, `--t-accent`, `--t-edge`, `--t-field`, `--t-hi`, `--t-ink`, `--t-label`, `--t-loss`, `--t-muted`, `--t-panel`, `--t-win`) are not in a token file at all. Each of five pages declares its own copy inside its own `<style>`: `mobile/home.html`, `mobile/gvm.html`, `mobile/check.html`, `mobile/models.html`, `mobile/qb.html`.

That is why `--t-sunk` exists on three call sites and zero declarations — with five copies to keep in step, a key added to one is a key missing from the other four, and here it was added to none. Five copies of a palette is exactly the "parallel token file" the card's own source of truth forbids, arrived at by drift rather than by decision.

**This is the single highest-value item in P3.** Fold the eleven keys into the one token file, delete the five copies, and add `--t-sunk` as the twelfth. It removes five duplicate palettes, closes the only genuine missing key on the app, and it is a plumbing change with no visual delta — which is this sprint's whole invariant.
